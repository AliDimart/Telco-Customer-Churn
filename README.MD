## Предсказание оттока клиентов телекоммуникационной компании
**End-to-end ML-проект** для предсказания уйдёт пользователь или нет.

Проект охватывает полный цикл разработки ML-модели: разведочный анализ данных, feature engineering, валидацию данных, предобработку признаков, обучение модели, подбор гиперпараметров, настройку порога классификации, логирование экспериментов, сериализацию модели и её развёртывание через REST API и веб-интерфейс. 

Данные: IBM Telco Churn из Kaggle (~7043 записей).

### Предобработка: 
 - Одной из основных задач является обработка **избыточной информации** в признаках интернет-услуг. В notebooks показано, что часть признаков связанных имеют избыточную информацию, в случае No internet Service. Поэтому в pipeline выполняется преобразование: No internet service → No, чтобы избежать добавления новых redundant dummie переменных 
 - Предобработка выполнена с помощью инструментов scikit-learn - SimpleImputer, OneHotEncoder
 - Также перед запуском основного пайплайна производится валидация качества данных с помощью **Great Expectations.**

 ### Подбор гиперпараметрво:
 - Для оптимизации гиперпараметров используется **Optuna.**
 - Для оценки используется кросс-валидация (StratifiedKFold). В качестве основной оптимизируемой метрики используется **Recall положительного класса**, поскольку цель - выявить клиентов, которые собираются покинуть компанию.
 - В проекте реализован отдельный подбор **threshold** на основе максимизации метрики **F2-score**, которая даёт больший вес метрике Recall.
 - Для отслеживания экспериментов используется MLflow.

 ### Реализованные технологии:
 - В папке scripts находятся скрипты для обучения модели, подбора параметров и предсказания модели.
 - Для взаимодействия с моделью через браузер реализован GUI на Gradio.
 - Для контейнеризации проекта используется Docker.

### Итоги: 
В качестве итоговой модели был выбран **XGBoost Classifier.** Выбор XGBoost обусловлен несколькими особенностями задачи:

- зависимость между характеристиками клиента и вероятностью оттока может быть нелинейной;
- между признаками существуют взаимодействия, например между типом контракта, интернет-услугами и способом оплаты;
- данные имеют дисбаланс классов;

XGBoost хорошо подходит под эти условия благодаря деревьям решений, способности моделировать нелинейные зависимости и взаимодействия признаков, а также встроенным механизмам регуляризации и решения проблемы дисбаланса классов через scale_pos_weight.

Подобранные гиперпараметры и threshold позволили добиться Recall = 0.901.
